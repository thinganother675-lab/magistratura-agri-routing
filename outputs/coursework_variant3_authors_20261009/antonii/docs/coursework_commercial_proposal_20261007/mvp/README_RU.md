## Что посмотреть за пять минут

1. Открыть демонстрацию с переменной погодой. Сопоставить расход воды и дни ниже порога у всех трёх планов.
2. Переключить погоду на засушливую и нажать «Сравнить планы». У модели нет гарантированного преимущества над правилами.
3. Изменить цену воды, площадь или инвестиции. После изменения нажать кнопку расчёта; до этого выгрузка старого отчёта отключена.
4. Открыть «Журнал решений»: дата, доза, прогноз, запас после симуляции и причина решения.
5. Открыть «Метод и данные», затем попробовать «Мой CSV» с приложенным образцом.
6. Скачать JSON-отчёт и CSV журнала. JSON содержит параметры, границы обучения/проверки, коэффициенты модели, SHA-256 входов, метрики и ежедневные результаты.

## Возможности

- Три плана: календарь, расчётный водный баланс, ML-прогноз.
- Синтетические показания за 60–365 дней: сухая, переменная или дождливая погода; фиксируемый seed.
- Обучение реальной Ridge-регрессии на первых 70% истории; проверка на последних 30%. Стандартизация только по обучающей части.
- Проверка ML и расчётного прогноза по MAE на наблюдённой истории.
- Контрфактическая симуляция трёх политик на одинаковом отложенном погодном ряде.
- Площадь, стоимость воды/перекачки, инвестиции, сопровождение, длительность сезона; сценарная оценка окупаемости только по воде.
- Изменяемые сценарные параметры водного баланса и жёсткий суточный лимит полива.
- Загрузка CSV, проверка дат, обязательных полей и числовых диапазонов. Пропуски не заменяются нулём.
- Резервный расчётный план при неправдоподобной зависимости прогноза ML от дозы.
- Локальный интерфейс на русском языке с адаптацией для узкого экрана.

## Результат демонстрационного эксперимента

Условия: seed 42, переменная погода, 120 дней, 8 га, остальные параметры по умолчанию. Обучение: 84 дня до 23 августа; проверка: 36 дней с 24 августа по 28 сентября. Даты относятся к искусственному летнему сценарию, а не к реальному хозяйству.

| Подход | Вода за симуляцию, м³ | Дней ниже сценарного порога |
| --- | ---: | ---: |
| Календарь | 16 000 | 0 |
| Водный баланс | 8 354,96 | 2 |
| Прогноз ML | 7 620 | 2 |

MAE модели на исторических проверочных наблюдениях — 1,419 мм; расчётного baseline — 1,513 мм. Эти MAE оцениваются на реальных для данного искусственного ряда исторических дозах, отдельно от симуляции альтернативных политик.

ML расходует на 52,38% меньше воды, чем календарь, но даёт больше дней дефицита. Это компромисс, а не доказанное улучшение. Календарная политика намеренно является простым сравнением, её параметры доступны пользователю. Эффект относительно неё не переносится на хозяйство с другим графиком. Относительно расчётной политики в этом сценарии ML использует меньше воды при том же количестве дней ниже порога; полевого подтверждения нет.

Иллюстративная экономика предполагает цену 12 ₽/м³, инвестиции 85 000 ₽, сопровождение 18 000 ₽/год и 120 дней полива в году. Упрощённая проекция по сбережённой воде даёт положительный результат, но не учитывает последствия дефицита, урожайность, полные затраты оборудования или сезонные денежные потоки. Она пригодна для исследования чувствительности, а не для обещания клиенту окупаемости.

## Формат CSV

[Образец полной истории](C:/sarychev/Codex/magistratura/docs/coursework_commercial_proposal_20261007/mvp/sample_sensor_history.csv) и [история без фактической погоды](C:/sarychev/Codex/magistratura/docs/coursework_commercial_proposal_20261007/mvp/sample_forecasts_only.csv) содержат синтетические данные. [Некорректный файл](C:/sarychev/Codex/magistratura/docs/coursework_commercial_proposal_20261007/mvp/sample_invalid.csv) нужен для проверки сообщения об ошибке.

| Поле | Смысл |
| --- | --- |
| date | Дата начала суток, YYYY-MM-DD, ежедневный порядок |
| soil_mm | Доступный запас воды в корневой зоне в начале суток, мм |
| rain_forecast_mm | Прогноз осадков, известный до решения, мм |
| et0_forecast_mm | Прогноз референсной эвапотранспирации до решения, мм/сутки |
| irrigation_mm | Историческая фактическая доза полива в этих сутках, мм |
| next_soil_mm | Наблюдённый запас после этих суток, мм |
| rain_actual_mm | Фактические осадки; нужны для симуляции альтернативных планов |
| et0_actual_mm | Фактическая ET0; нужна для симуляции альтернативных планов |

Первые шесть полей обязательны, от 30 до 365 наблюдений. Без двух последних доступны обучение, проверка прогноза и предложение полива; сравнение стратегий и экономика выключены. CSV поддерживает запятую или точку с запятой как разделитель; десятичный разделитель — точка; кодировка UTF-8, BOM допустим.

Запас в мм не равен сырой влажности датчика в процентах. Реальным датчикам нужны калибровка, глубина корневой зоны и параметры почвы. Если прогностические погодные поля подменены фактическими данными будущего, оценка не отражает реальный прогноз. Приложение не может доказать время происхождения чужого CSV; это обязанность подготовки входов.

После загрузки показания используются в памяти локального запроса. Сервер не записывает загруженные CSV на диск. Нажатие «Скачать отчёт» сохраняет выбранную пользователем выгрузку в браузере.

## Модель и границы

Прогнозируется запас воды после суток по четырём признакам: текущий запас, прогноз осадков, прогноз ET0, предложенная доза. Ridge-регрессия реализована на уже установленном NumPy, alpha = 1.0. Модель не является LLM и не нуждается в ключе API. Ограничения и подбор дозы выполняет расчётная политика.

Упрощённая модель состояния:

```text
запас после суток = clip(запас + осадки + эффективность × доза − Kc × ET0, 0, ёмкость)
```

Она использует идеи водного баланса, но не реализует полностью FAO-56, не вычисляет ET0 из метеопараметров и не моделирует урожайность. Избыток выше ёмкости считается дренажом. Реальные сток, эффективные осадки, капиллярный подъём, стресс-зависимая транспирация, солёность и динамика корней отсутствуют.

Все коэффициенты, пороги и цены — вводимые сценарные параметры. Предложение полива относится к дате последней строки и её входам, а не к текущей календарной дате. Оно требует предметной проверки; оборудование не подключено.

Источники: [FAO-56, водный баланс](https://www.fao.org/4/X0490E/x0490e0e.htm), [FAO CROPWAT](https://www.fao.org/land-water/resources/tools/software/cropwat/en). Они служат предметными ориентирами, а не доказательством точности текущей реализации.

## Проверка

24 автоматические проверки покрывают баланс и единицы, ограничение дозы, временное разделение, независимое восстановление линейной зависимости, плохие входы, пропуски погоды, отсутствие окупаемости при отрицательном эффекте, резервную политику и HTTP-контур. Временное разделение дополнительно проверено изменением только будущих целевых значений: обученные коэффициенты и параметры стандартизации остаются прежними.

В браузере проверены загрузка страницы, пересчёт сухого сценария, загрузка полного CSV через форму, отрицательная экономика при нулевой стоимости воды, скачивание JSON, отсутствие ошибок консоли и раскладка шириной 390 пикселей без горизонтального переполнения. Выгруженный браузером JSON совпал с сохранённым результатом Python.

Дополнительно прошли 68 существующих проверок `test_lab.py` и `test_home_stats.py`. Суммарно 92 проверки прошли; весь набор прежних экспериментов повторно не запускался. CSV журнала содержит 36 дней; сумма доз совпадает с JSON-отчётом. Полная браузерная проверка выполнена на локальном порту 8094; первая попытка на 8093 была недоступна и не считалась успешной.
