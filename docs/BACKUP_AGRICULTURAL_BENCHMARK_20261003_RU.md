## Почему выбран BhashaBench-Krishi

[Авторская карточка BharatGen](https://huggingface.co/datasets/bharatgenai/BhashaBench-Krishi) заявляет **15 405** текстовых экзаменационных заданий: **12 648 English**, **2 757 Hindi**. Английский `test` соответствует пожеланию дополнить русскую MERA; предметный gold берётся у внешних создателей, не конструируется Антонием и Денисом. Карточка указывает **CC BY 4.0**. Анонимный API подтвердил эту декларацию, конфигурации `English/test`, `Hindi/test` и ревизию `a5b8797e4ff2db2e50f761a39f91b1d9749e78fd`. Числа строк пока **заявлены авторами, не перепроверены в файле**.

[Devane et al., BhashaBench V1, arXiv:2510.25409](https://arxiv.org/html/2510.25409v1), §3.2–3.3 и C.1, описывают официальные экзамены с предметными ключами, OCR/структурное извлечение с GPT-OSS-120B и последующую экспертную проверку. Это **expert-derived / expert-verified** набор; формулировка «все задания вручную созданы экспертами специально для benchmark» была бы неточной. Изображения исключаются в методике создателей. Публикация в этом аудите подтверждена как препринт; рецензируемый venue не установлен.

Текущая карточка **gated**: для доступа нужно принять условия и согласиться на передачу контактных данных. Metadata доступны анонимно, прямой raw README вернул **HTTP 401**. Доступ не обходился. CC BY 4.0 — подтверждённая декларация набора, а условия получения ещё не приняты и не проверены человеком. MIT в репозитории кода относится к коду, не заменяет условия данных. Научная рекомендация сама по себе не разрешает автоматическую передачу контактов.

## Scoring и независимость

Статически проверены [официальный шаблон](https://github.com/kundeshwar-BharatGen/BhashaBench/blob/babd1e1d97d5361da53fe1f11b941400399206e0/lm_eval/tasks/bbk/_default_template_yaml), [English task](https://github.com/kundeshwar-BharatGen/BhashaBench/blob/babd1e1d97d5361da53fe1f11b941400399206e0/lm_eval/tasks/bbk/bbk_English.yaml) и [utils_bbk.py](https://github.com/kundeshwar-BharatGen/BhashaBench/blob/babd1e1d97d5361da53fe1f11b941400399206e0/lm_eval/tasks/bbk/utils_bbk.py) на ревизии кода `babd1e1d97d5361da53fe1f11b941400399206e0`. Шаблон использует `test_split: test`, `output_type: multiple_choice`, `acc` с усреднением. Эталонное поле `correct_answer` переводится из A–D в индекс; prompt строится только из `question` и четырёх `option_*`. Эталон в prompt не включается. Наличие схемы в коде подтверждено; фактические значения файла и локальный scoring ещё не проверены.

В статье локальные модели оцениваются через conditional log-likelihood вариантов, а API — через структурированную генерацию. Для LM Studio разумна единая **generative choice accuracy** с заранее зафиксированным parser; её нельзя представлять как точное воспроизведение log-likelihood leaderboard. Сравнивать модели внутри одного протокола, сохранить invalid-format rate и latency; не объединять баллы с MERA.

До текущего аудита поиск `BhashaBench`, `AI AgriBench`, `AGREASON` в `docs`, `experiments`, `manuscript`, `results` не нашёл прежних записей. Признаков использования BBK для project model selection не найдено. Это проверка доступных артефактов, не гарантия отсутствия любой неизвестной внешней exposure. Полный exact/semantic/source overlap с HOME150/MERA/AgXQA ещё не проверен: содержимое BBK не приобретено.

Экзамены публичны; неизвестно, входят ли они в pretraining Qwen/Gemma/cloud моделей. Публичный выпуск после некоторой даты не доказывает отсутствие contamination. Индийские региональные знания и политика отличаются от России: резерв даст независимое **англоязычное экзаменационное** свидетельство, не проверку качества советов для Московской области.

## Что делает резерв READY

1. Человек решает, допустимо ли принять HF gate и передачу контактов. Никаких новых расходов/аккаунтов/условий агент самостоятельно не создаёт.
2. После законного доступа получить **один** pinned `English/test` файл, зафиксировать SHA-256, count, schema, source/exam grouping и дубли; проверить возможные EN/HI пары и project overlap. Числа card перестанут быть только declarations.
3. Зафиксировать модели, prompt, отсутствие tools/search/RAG, output budget, parser, scoring, selection/grouping и размер до inference. Для умеренной нагрузки можно заранее задать deterministic стратификацию, независимую от model correctness; не подбирать её по gold.
4. Верифицировать scorer на synthetic fixtures и semantics официального кода. Если используется генерация, явно назвать её собственным generative protocol.
5. Выполнить один заранее замороженный независимый test после завершения DEV-выбора; не превращать ошибки резерва в очередную настройку той же подтверждающей оценки.

Сейчас выполнены declaration/expert/code audits; acquisition, label inspection, overlap audit, scorer reproduction и protocol freeze отсутствуют. **READY не заявляется.** Это ограничение не останавливает Qwen systems telemetry, Study C и DEV-анализ. В машинной записи и fail-closed validator сохранён `inference_run=false`; structural tests не заменяют права, экспертов или научное adjudication.
