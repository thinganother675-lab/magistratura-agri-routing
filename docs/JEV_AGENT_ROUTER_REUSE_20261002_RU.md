В документации старого repo заявлена acceptable accuracy SIMPLE95.2% на первом run147-test subset из226skill-routing cases, official-default84.1%, tuned-official92.4%, hybrid95.2%; там же указано, что разница между SIMPLE/tuned/hybrid не установлена и второй Jev call не показал ясной пользы. Это **DOCUMENTED HISTORICAL CLAIM**, не независимо пересчитанный результат: prompts, labels, frozen snapshots и per-case raw отсутствуют в Git и исключены `.gitignore`. Task — selection специализированных coding skills, metric — acceptable classification с исключением ambiguous cases; эти95.2% не переносим в agricultural answer correctness. Цифры не добавлены как новая verified research table или научная citation.

Найдены ограничения старого кода, которые не следует переносить:

- `jev_client.DEFAULT_MODEL` по умолчанию `jev-latest`; текущий аграрный run фиксирует jev-1.13.0 и проверяет returned identity.
- `Router._post` может повторить POST один раз после transport failure. Component latency включает только последнюю попытку; `Router.decide` при исключении возвращает latency0/input0/cost0. Однако `benchmarks/router_variants.Simple/Official/Hybrid` оборачивают весь `decide` собственным t0: их top-level latency включает elapsed retry delay. Внутренние retries всё ещё не полностью отражаются в calls/tokens/unknown charges benchmark variants; нельзя утверждать, что все старые benchmark latency исключают retries. Наш текущий driver делает retries0, journal каждой actual attempt и UNKNOWN usage при timeout. Это различие подтверждено независимым subagent code review, который не является human validation.
- Thresholds0.45/0.75 и confidence calibration относились к другим data/catalog и не доказывают вероятность правильного аграрного ответа. Их не копировали.
- `overall_confidence` — geometric aggregation отдельных typed-field confidences, не empirically calibrated answer confidence. Distance noul от0.5 также не доказывает calibration.
- Старый `Router._interpret` не полностью проверяет closed enum/type/range; он вызывается за пределами try в `Router.decide`, поэтому malformed response может нарушить заявленный fail-open. В `agent_decider._choice` non-finite confidence не отклоняется явно. Этот parser не переносили; текущий аграрный normalizer и unit tests проверяют typed bounds. Семь agent questions составляют один пакет для `/agent_decide`; совместное `/decide`+`/agent_decide` означает два upstream packets, не один.
- `router_scoring.py` использует paired bootstrap по отдельным cases, не whole-source groups, а ambiguity excluded из main denominator. Наш DEV публикует все36 и whole-group resampling, оставляя ограничения групп.
- `desc_experiment.py` включает отдельный warm-up и явно переводит ранее наблюдавшийся blind50 в DEV. Description ablation полезна как development experiment; её нельзя представить новым blind holdout или переносить непоказанный warm-up в latency comparison.
- Прежние connection/proxy/geolocation наблюдения относятся к другой машине/дате. Они не подтверждают нынешний network path и не дают оснований менять proxy/обходить provider restrictions.

Практический вывод: наиболее сильная переносимая идея — **один typed choice со встроенным отказом, небольшой описанный каталог и локальная проверка входов**. Это совместимо с текущей архитектурой, но не устраняет отрицательный результат [нового comparison](PREROUTING_COMPARISON_20261002_RU.md): Jev30/36 против rule31/36, генеративные23→20 и все внешние23→56. После human gold audit возможна одна отдельная абляция descriptions/packet size на DEV, затем новый external group-split freeze. Не следует добавлять second-stage reranking или заменять generators только ради лучших цифр на уже просмотренных заданиях.

Для независимого воспроизведения прежних95.2% нужны локальные original prompts/labels/run manifests соответствующего ноутбучного проекта и подтверждение прав/consent. Их отсутствие не блокирует нынешние local/OpenRouter/статью задачи; чужие private stores не искались.
