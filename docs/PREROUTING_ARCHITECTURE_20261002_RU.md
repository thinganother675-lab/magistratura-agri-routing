# Предварительная маршрутизация: новый exploratory этап

Дата разработки: 02.10.2026; фактическое UTC начала каждого запуска хранится в protocol.json. Исторические 90/150 результатов и замороженные adapters не изменены. Регрессионная проверка старой статистики и шести core SHA прошла; до новых изменений 241 тест PASS.

Новый интерфейс `agro_route.prerouting.decide_pre` выбирает TOOL / LOCAL / CLOUD / CLARIFY / ABSTAIN **до генерации ответа**. Jev получает один пакет из двух типизированных вопросов. `missing_data` диагностический: route choice выбирает направление, а deterministic gate окончательно проверяет numerical completeness. Laya отвечает на те же вопросы локально на CPU. Правило служит обязательной простой абляцией. Selector получает только публичный вопрос, context, разрешённые числовые поля, требования инструментов и сетевые ограничения; gold, category, expected route и correctness отсутствуют.

После selector общий deterministic hard gate проверяет инструменты, units и отсутствующие/недопустимые поля. Его override записывается отдельно: успех инструментов нельзя приписывать Jev/Laya. Числовые scenario fields сохраняются, даже когда они не являются входами отдельного инструмента. Ни один LLM не заменяет GDD/VPD/ET0/rain deficit.

Общий для трёх pre-routing методов защитный heuristic отправляет LOCAL в CLOUD при явных признаках conjunction/negation, нескольких подписанных сущностях или длинном context; offline превращает этот запрос в ABSTAIN. Это ограниченный лексический guard, не доказательство entailment или агрономической правильности. Старый каскад сохраняет собственный literal-grounding verifier. Поэтому сравнение с каскадом содержит явно отмеченный дополнительный фактор guard; primary сравнение Jev-first versus rule-first использует одинаковые guards.
