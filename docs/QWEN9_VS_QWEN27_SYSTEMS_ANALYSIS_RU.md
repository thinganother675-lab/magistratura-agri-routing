# Qwen9 и Qwen27: качество и ресурсы локального исполнения

Дата: 3 октября 2026. Авторы проекта: Antoniy Sarychev и Denis Shesternin,
РГАУ-МСХА имени К.А. Тимирязева. Статусы: **DEV** для исторического качества и
**SYSTEMS_TELEMETRY** для новых измерений. Независимое подтверждение отсутствует.

## Вывод и границы гипотезы

Qwen3.5-9B занимает благоприятную область качества и ресурсов на этой машине:
сохраняет 94% наблюдаемого EM Qwen3.8-27B при существенно меньших задержках,
размере весов и занятой памяти. Qwen27 при этом имеет более высокий EM и дал
больше правильных самостоятельных ответов Study C в наблюдавшихся разных
профилях исполнения. Нет основания объявлять Qwen9 универсальным
победителем или доказанно не хуже Qwen27. Допустимая потеря качества и ресурсный
бюджет должны быть согласованы до независимого итогового испытания.

## Историческое качество: один и тот же DEV293

Использованы сохранённые полные ответы; DEV293 заново не запускался. Из 293
примеров 289 имеют исходный разбираемый эталон; четыре проблемы кириллических обозначений
не исправлялись семантически. Метрики STRICT_SET_EM/F1 не являются официальными
результатами MERA. На всех 293 завершено получение ответов без ошибок транспорта
и без невалидного набора вариантов у этих трёх моделей.

| Модель | EM | F1 | Историческая p50 / p95, с | GGUF, GiB | Квантизация |
|---|---:|---:|---:|---:|---|
| Qwen3.5-9B | 141/289 = 48,79% | 0,6286 | 0,295 / 0,402 | 8,873 | Q8_0 |
| Qwen3.8-27B | 150/289 = 51,90% | 0,6468 | 1,374 / 1,753 | 15,334 | UD-Q4_K_M |
| Gemma4-26B-A4B | 147/289 = 50,87% | 0,6671 | 0,807 / 0,948 | 13,557 | UD-IQ4_NL_XL |

Qwen9 − Qwen27: **−3,11 процентного пункта EM**, −0,01816 F1; отношение F1
97,19%. Парные исходы: обе верны 113, только Qwen9 28, только Qwen27 37,
обе неверны 111. Описательный стратифицированный по дисциплине bootstrap:
95% интервал разницы EM [−8,30; +2,42] п.п. Он не учитывает всю неопределённость
выбора моделей на DEV и не доказывает эквивалентность. Разрезы по дисциплинам и
числу правильных вариантов, распределения и исходные ссылки:
[DEV-анализ](QWEN9_VS_QWEN27_DEV_ANALYSIS_20261003_RU.md),
`results/20261003_resource_analysis/analysis.json` и CSV в той же папке.

Название параметрического размера относится к языковому компоненту согласно
[Qwen9](https://huggingface.co/Qwen/Qwen3.5-9B),
[Qwen27](https://huggingface.co/Qwen/Qwen3.8-27B) и
[Gemma](https://ai.google.dev/gemma/docs/core); это не пересчёт всех тензоров
зрения/MTP. Gemma26 — MoE с приблизительно 4B активных параметров. Размеры выше —
основной GGUF, без отдельного проектора. SHA256 Qwen9/Qwen27 повторно проверены
до измерений и совпали с исторической записью. Разные квантизации являются
частью сравниваемых практических конфигураций; влияние архитектуры и квантизации
этим опытом не разделяется.

## Отдельный TELEMETRY40

Выбор заранее и без правильности ответов: четыре равномерно расположенных ID
в каждой из десяти дисциплин DEV. Даже/нечётные позиции образуют два блока
по 20, каждый содержит все дисциплины. Порядок модельных блоков ABBA:
9B, 27B, 27B, 9B. Один контроллер, concurrency=1, явная выгрузка, стабилизация
памяти и один синтетический прогрев после каждой загрузки. Обе модели получили
ровно те же 40 запросов. Study C проходил отдельно и не входит в таблицу ниже.

Машина: Ryzen 7 8700F, RTX 5060 Ti 16 GB (16311 MiB), 31,620 GiB RAM.
LM Studio 0.4.25+1; глобально выбран llama.cpp CUDA12 runtime 2.51.0,
точная сборка движка каждой модели не экспонируется. Контекст 2048, температура
0, top_p=1, максимум 512 токенов, reasoning=off, parallel=1, MTP выключен,
flash attention включён. Native REST не предоставляет документированный seed
и JSON schema в использованном режиме. Нельзя считать новый транспорт полностью
эквивалентным историческому OpenAI-compatible режиму.

## Завершённый профиль V2

`20261003_systems_checkpoint0_v2`: context_checkpoints=0, eval_batch_size=2048;
значения проверены в ответе загрузчика. Размещение GPU автоматическое: доля
offload и фактическое число GPU layers **UNKNOWN**. Это отдельный профиль,
отличный от исторических запросов `--gpu max` / `--gpu 0.75`.

|---|---:|---:|
| Средняя задержка, с | 0,279 | 1,513 |
| p50 / p90 / p95, с | 0,269 / 0,325 / 0,344 | 1,434 / 1,769 / 1,829 |
| Клиентская TTFT p50 / p95, с | 0,122 / 0,189 | 0,691 / 0,928 |

| Генерация backend p50, токен/с | 40,33 | 7,56 |
| Whole-GPU sampled peak, MiB | 11471 | 13287 |
| Whole-system RAM sampled peak, GiB | 20,858 | 28,470 |
| LM Studio process-group RSS peak, MiB | 11198,96 | 18742,34 |
| Транспорт / stream completion | 40/40 | 40/40 |
| Нарушения JSON object presentation | 2/40 | 0/40 |

Медианное ускорение Qwen9 **5,338×**; уменьшение пиков whole-GPU 1816 MiB и
whole-system RAM 7,612 GiB. Это значения устройства/системы, включая фоновые
процессы, и sampled peaks; они не являются выделенной памятью весов модели.
Process-group RSS также включает UI/службы и может включать другой процесс с
разрешённым basename либо повторно считать shared pages; это не lineage-aware
измерение выделенной памяти модели. Снимки до/после
и распределения пиков сохранены. Обычные приложения рабочего стола и небольшой
CLI-процесс облачного теста оставались активны. Тяжёлые GPU-задачи и загрузки
не запускались. ABBA уменьшает, но не устраняет временной/температурный сдвиг.

Две загрузки Qwen9: 17,289 и 21,354 с; Qwen27: 19,820 и 9,859 с.
Прогревы: Qwen9 0,241 и 0,506 с; Qwen27 1,329 и 1,348 с. Эти два наблюдения
зависят от кеша ОС и не оценивают холодную загрузку или её p95. При n=40 p99
слишком нестабильна для основного вывода: первичная сводка сохранена,
исправленный агрегат использует p99=null.

Задержка — полный HTTP round trip; подготовка инструментальных снимков до
HTTP и финальный снимок после HTTP в неё не включены. UTC request записан
перед подготовкой снимков, поэтому его нельзя вычитать из end_utc для подмены
монотонного HTTP таймера. Клиентская TTFT — время от старта HTTP до первого answer delta; backend TTFT
является отдельной метрикой сервера. Скорость input_tokens / client prompt span
сохранена как token-equivalent rate, поскольку кеширование не позволяет выдать
её за чистую скорость prefill. Native chat.end подтверждает завершение потока,
но не причину EOS/stop; finish reason **UNKNOWN**. Seed и энергия также UNKNOWN /
NOT_ESTIMATED. Whole-GPU power samples не преобразованы в энергию запросов.

## Сохранённый отказ V1

Первый профиль `20261003_systems_study_c_v1` использовал 32 context checkpoints.
Qwen9 завершил 40 системных + 27 Study C запросов. Qwen27 получил 21/40 системных
ответов; 19/40 системных и 27/27 Study C попыток остановлены RAM guard. Минимум
свободной RAM около 0,55 GiB. Эти отказы не являются арифметическими ошибками.
Короткие времена остановленных запросов не включаются в сравнительную медиану.

Первая запись COMPLETE означала завершение всех попыток, а не успешных ответов;
исправленная независимая QA-квитанция хранится рядом без перезаписи исходников.
После диагностики checkpoint cache обе модели прошли тот же TELEMETRY40 в V2.
DEV293 не повторялся. Qwen9 Study C использован из уже завершённого V1,
Qwen27 Study C получен в V2 после операционного отказа. Смена профиля раскрыта,
плохие ответы Qwen9 не переснимались. Повторяемость на другом дне/машине ещё
не проверена; отсутствие ошибки V2 не доказывает универсальную устойчивость.

## Телеметрия для следующих опытов

`src/agro_route/lm_telemetry_20261003.py` отделяет native SSE, проверку единиц,
тайминги и ресурсы. Запуск должен сохранять совместно: frozen protocol с моделью,
GGUF SHA256/размером, версиями и настройками; load/warmup receipts; metrics;
resource samples и точные request/response в закрытом ignored `.runtime`.
На каждой записи есть UTC, task ID, SHA/размер промпта, серверные токены,
клиентские интервалы, результат разбора и scope памяти. Настройки запроса
связаны через protocol и request SHA. Safe projection исключает тексты, ключи
и заголовки. Не экспонируемые настройки сохраняются как UNKNOWN, а не угадываются.
Фиксированная схема не обещает воспроизведение скрытого backend поведения.

Машиночитаемые результаты: `results/20261003_systems_checkpoint0_v2/`;
исторический Gemma reference не получил новую телеметрию. Не вводится
произвольный скалярный efficiency score. Pareto-графики показывают tradeoff,
но не выбирают допустимую потерю качества за авторов.
