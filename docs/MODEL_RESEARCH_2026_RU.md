# Исследование дополнительных моделей на 01.10.2026

Статус: research only для дополнительных генеративных и аграрных моделей; их новых весов не скачивали и доменные модели не запускали. Отдельно по разрешению пользователя скачан и CPU-tested негенеративный открытый decision baseline Laya multilingual — см. `JEV_LOCAL_ALTERNATIVE_RU.md`. Он не входит в ranking генеративных ответов. Приоритет сессии — измерение уже установленных домашних моделей. Собственные development результаты находятся в `LOCAL_MODEL_COMPARISON_RU.md`; здесь не повторяется leaderboard, и не выбирается победитель по чужим benchmark заявлениям.

Дополнительная загрузка сейчас не обоснована: в наличии есть несколько архитектур/размеров, а причины проблем надо разделить на возможности модели, prompt/schema, CLI/HTTP transport и CPU offload. Для исследования доменной адаптации достаточно впоследствии добавить **один** baseline, после фиксации базового протокола и проверки русского качества.

Оценки P×bits/8 показывают нижнюю границу payload. Quantization metadata, scales, vision, KV/state cache, backend buffers и операционная память добавляются отдельно. Ни одна строка не доказывает fit, offload или tok/s на домашней машине. MoE уменьшает активные вычисления, но не устраняет хранение experts; сравнивать **измеренные** RAM/VRAM, TTFT и полный ответ.

## Данные полезнее ещё одной загрузки

[AgXQA, Computers and Electronics in Agriculture 2024](https://www.sciencedirect.com/science/article/pii/S0168169924007403) и [DEW/FLOW, тот же журнал, 2026](https://www.sciencedirect.com/science/article/pii/S0168169926001286) дают внешний irrigation/water-management контекст. DEW содержит 419 логико-математических вопросов по 24 доменам. Перед включением нужны download/license/provenance audit, независимость от dev, проверка переводов и numerical gold. Не превращать весь published benchmark в holdout после просмотра ответов при настройке.

[AgroTools 2026](https://arxiv.org/abs/2605.22366) и [AgriAgent 2026](https://arxiv.org/abs/2601.08308) — близкий prior art для executable tools и orchestration. Их полная репликация не выполнялась. Научные papers идут в bibliography; HF/GitHub здесь нужны для идентификации release и не входят в университетский минимум научных ссылок.

## Решение для этой сессии

Продолжать уже установленный pilot. После исправления контролируемого HTTP schema/settings и восстановления разрешённого cloud API зафиксировать selected model/router и затем провести новый independent holdout один раз. Если последующий dev подтвердит именно пробел в domain knowledge при приемлемой русской грамматике/schema, рассмотреть PLLaMa-7B-instruct как один **supplemental** baseline с отдельной лицензионной и русской проверкой; сначала сверить точный quantized release, размер, свободный диск и expected role. Данных для утверждения, что новая аграрная модель превосходит уже установленную GPT-OSS/Qwen на наших задачах, пока нет.
