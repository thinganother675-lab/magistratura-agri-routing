Диагноз и междоменные последствия
P1 — обязательный допуск: правильность, полнота, полномочия и сохранность локальной записи. P2 — оптимизация времени после выполнения P1. ПЗ-3–9 дают согласованные Р, DOC, OP, APP и T. Дефект PR-01 требует одновременно дисциплины OP в источнике и прикладного контроля, поэтому один новый сервер его не устраняет. Для PR-02 масса сопровождается исключениями и полнотой; для PR-03 нужны локальное сохранение и последующая доставка. Влияние объёма данных на производительность не измерено и не объявляется главной причиной.
Ответ на новое условие
Невыполненным останется REQ-01: M01 и M03 уникальны как message_id, но обозначают один OP-101. В требовании фиксируем однократный вклад по operation_id и неизменяемому содержанию в границе С01. Проверка должна повторять одну выдачу с разными message_id и проверять сумму и решения по строкам. Для одинакового OP с разным содержанием отдельно действует REQ-02.
Применение ИИ и агентная проверка
Для каждого из пяти REQ указан метод проверки; тесты модели не распространены на права, сеть и время подготовки отчёта.

Последствие и приоритет
PR-01: M01/M03; К03/К06
Повтор файла → тот же OP → APP-03 суммирует строку снова.
Завышение свода; высокий приоритет, правильность важнее скорости.
PR-02: M04–M07; К02/К06
Пропуск/ожидание/конфликт → нет списка нерешённых → Р04 видит только массу.
Ложное впечатление полноты; высокий приоритет.
PR-03: T04; К05
Недоступна связь → файлы/подтверждения задержаны → общий отчёт неполон.
Сохранить локальные записи и явно показать состояние; высокий приоритет.
