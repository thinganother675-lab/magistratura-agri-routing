Что новичку нужно понимать
GAMS получает записанную математическую модель, затем решатель подбирает
значения неизвестных. Для задачи производства это четыре объема выпуска,
ограниченные сырьем и временем оборудования; цель -- максимальная выручка.
Данные задаются отдельно от переменных. Positive Variables означает x >= 0,
включая ноль. Обычная Variable по умолчанию свободная по знаку.

Минимальная схема записи, не решение конкретного варианта:
    Positive Variables x1, x2;
    Variable z;
    Equations revenue, resource;
    revenue.. z =e= 2.4*x1 + 2.7*x2;
    resource.. 1.01*x1 + 1.01*x2 =l= 140;
    Model demo /all/;
    Solve demo using lp maximizing z;
    option decimals=3;
    Display x1.l, x2.l, z.l, demo.modelstat, demo.solvestat;
Эта иллюстрация намеренно неполная: реальные ограничения оборудования
и дополнительного продукта надо перенести из подтвержденного варианта.
Операторы заканчиваются точкой с запятой. Десятичный разделитель -- точка.
Присваивание параметру: =. Равенство в ограничении: =e=.
Для LP нельзя незаметно добавлять произведения переменных или делить на них.

Запуск и приемка результата
Сохранить текст модели в .gms; открыть в установленном редакторе GAMS
или вызвать gams model.gms из каталога проекта. Точную команду с путем
и доступный интерфейс проверяет агент установки после реального запуска.
Нужен .lst с SOLVER STATUS 1 Normal Completion и MODEL STATUS 1 Optimal
для данной линейной задачи. Само отсутствие ошибки запуска не доказывает
оптимальность. Затем прочитать .l объемов и цели, подставить ответ в КАЖДОЕ
ограничение, сравнить расход с запасом, проверить неотрицательность и единицы.
При синтаксических ошибках сначала исправлять первую по порядку: часто
причина -- забытая точка с запятой в предшествующей строке.

Отчет и точность -- предлагаемое оформление, не новое требование курса
Достаточная основа: условие и вариант; четыре неизвестных с единицами;
развернутая математическая модель; исходный .gms; результат и статусы;
компактная таблица ресурсов (лимит, расход, остаток); экономический вывод.
Листинг -- приложение и доказательство запуска, сам по себе он не заменяет
объяснение модели и результата. Сверить формат с заданием преподавателя.
Из прежнего аудита курса: первая назначенная работа -- №2, пункт 2;
преподавателю требуется показать математическую запись до работы в GAMS.
Актуальное назначение и номер варианта перепроверяет агент аудита курса.

Слова пользователя о 4-5 числах трактуем как разумную краткость и, при
необходимости, 4-5 значащих цифр для итогов, а не ослабление корректности.
Исходные коэффициенты оставлять как в задании; расчеты и проверки делать
с полной точностью; округлять только представление в отчете. Например,
123.456 -> 123.5 (4 значащие цифры), 0.0123456 -> 0.01235 (4 цифры).
option decimals=3 управляет количеством знаков ПОСЛЕ точки в Display,
это не команда на 3 значащие цифры и не настройка точности решателя.
Не округлять оптимальный производственный план до целых без повторной
проверки ограничений: можно получить недопустимый расход ресурсов.

Ограничения старого перевода
В русском файле встречаются опечатки синтаксиса: c(i.j), aqrt, x,m,
потерянные скобки в sum. Копировать его примеры без проверки нельзя.
Правильные формы: c(i,j), sqrt(...), x.m, sum((i,j), выражение).
Там же старые ограничения длины имен и типа Integer; современную версию
сверять с английской документацией и фактически установленным GAMS.
Для совместимости с учебной версией разумно использовать короткие
латинские имена и ASCII-комментарии внутри .gms, русский текст -- в отчете.
