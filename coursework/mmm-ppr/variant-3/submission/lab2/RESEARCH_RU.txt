СПРАВОЧНЫЕ ПРИМЕРЫ И МЕТОДЫ
Основные условия варианта 3 взяты из методички курса и сверены с изображениями страниц 15, 41 и 56. Официальные примеры и обсуждения ниже ранее проверены при подготовке варианта 11 и использованы как справка для самостоятельно рассчитанного варианта 3. Отдельный поиск готового чужого решения варианта 3 не проводился.

1. Официальная загрузка и установка GAMS
https://www.gams.com/download/
https://www.gams.com/latest/docs/UG_WIN_INSTALL.html
На дату проверки версия 54.5.0. В дистрибутив включена демонстрационная лицензия с ограничениями размера; наши модели фактически успешно выполнились. Установщик получен из ссылки страницы на официальный сервер загрузки, а не со стороннего зеркала. SHA256 52367763eb69dae1b9eeee5f3023715ed851d9184f875da689c8b3fae955a1b2 совпал, цифровая подпись GAMS Development Corporation действительна. Установлено для текущего пользователя в runtime/gams/54.5. Лицензия принята пользователем отдельно перед скачиванием/установкой.
Официальные проверочные примеры: trnsport=153,675; chenery=1058,9199. Они успешно выполнены. Код этих примеров использован только для проверки среды.

2. Официальный пример анализа эффективности
https://www.gams.com/latest/gamslib_ml/libhtml/gamslib_dea.html
Полезен как образец объявления данных, переменных, прямой/двойственной задачи линейного программирования и различия постоянной и переменной отдачи от масштаба. Библиотечный пример имеет ориентацию на ресурсы. В нашем исходнике самостоятельно записана модель с ориентацией на выпуск и переменной отдачей от масштаба по примеру лекции преподавателя, поэтому нельзя переносить библиотечную цель/нормировку автоматически.

3. Экспорт сценариев
https://www.gams.com/latest/docs/UG_Put.html
Использован Put: каждый сценарий сохраняется в отчётный параметр; после циклов строки записываются в текстовый CSV. Ширина файла увеличена, чтобы длинные строки не переносились. Итоговый UTF-8 TSV сформирован из проверенных GAMS-данных, а не из подменяющего расчёта.

4. Форум: результаты нужно сохранять ВНУТРИ цикла
https://forum.gams.com/t/export-looped-tables-to-excel/1681
Смысл обсуждения: если экспортировать только переменную после цикла, останется последний запуск. Для нескольких сценариев собирается параметр с индексом сценария на каждой итерации. Этот подход применён в lab8.gms к решениям, статусам и множителям.
https://forum.gams.com/t/how-to-quickly-load-data-over-a-loop-different-scenarios/1680
Полезен общий принцип таблицы условий с индексом сценария. Для этих малых работ выбран простой читаемый CSV -> GAMS Table, без обязательной внешней Excel-связки.
https://forum.gams.com/t/loop-for-objective-function/2419
Полезен совет разделить скалярную цель и параметр сохранённых результатов. Конкретная чужая формула цели не переносилась.

5. Статусы нужно читать по документации
https://www.gams.com/latest/docs/UG_GAMSOutput.html
Для задачи линейного программирования modelstat=1 означает оптимальное решение; для нелинейной модели modelstat=2 означает локальное оптимальное решение; solvestat=1 означает успешное завершение расчёта. Отдельная численная проверка глобальности приведена в отчёте. При неприемлемом статусе или нарушении допусков расчёт завершается ошибкой.

6. Спирмен: маленькая выборка и совпадения
https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html
https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.permutation_test.html
Документация рекомендует для маленьких выборок учитывать перестановочную проверку. Поэтому вместе с приближением по распределению Стьюдента рассчитано двустороннее p по |ρ| на 200 000 перестановок с фиксированным начальным числом генератора. Использованы средние ранги для совпадений. Наше абсолютное двустороннее правило задано явно; оно может немного отличаться от определения «удвоить меньший хвост» в конкретной функции permutation_test при дискретной асимметричной статистике.

ИТОГ ИССЛЕДОВАНИЯ
Использованы проверенные методы и примеры синтаксиса, а не готовая чужая лабораторная. Числа, модели и выводы получены для данных №3 и сверены независимыми задачами. Замена переменных в №8 и касательная верхняя оценка разработаны для конкретных показателей рассматриваемого варианта; они не выданы за универсальный приём при любых эластичностях.
